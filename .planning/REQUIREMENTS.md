# Requirements: PageFolio v1.10.0 多重起動防止・起動操作の改善

**Defined:** 2026-10-21
**Status:** Approved — 2026-10-21 にユーザーが15要件と保証範囲を承認。ロードマップ作成・承認後にフェーズ計画へ進む。
**Core Value:** 大きな PDF でも Undo/Redo が正しく・速く動作し、コードが読みやすく保守しやすい状態にする。

## Scope and Confirmation

2026-10-21 にユーザーが採用した4項目（多重起動防止、既存画面の復元・前面表示、設定読込・保存失敗通知、配布ビルド改善）を具体化した承認済み要件。

調査により判明した次の保証範囲を、本一覧と合わせてユーザー確認済み。

1. 同一 Windows ログインセッション内の排他は、本機構に対応した PageFolio 同士を対象とする。対応版同士では版番号・配置先・Python/EXE を問わない。機構のない既存旧版 EXE までの相互排他は保証しない。別ログインセッションは独立する。
2. 既存画面は復元して前面化を試みる。Windows が前面化を拒否した場合は、タスクバー強調などの視覚的な通知で案内する。OS の制約を迂回して強制的に入力フォーカスを奪わない。
3. 今回の設定失敗通知は `pagefolio_settings.json` の読込・保存を対象とする。外部プロンプトファイル保存失敗の通知改善は、サンプル同梱とは別の保留項目とする。

## v1.10.0 Requirements

### 多重起動防止

- [ ] **V110-START-01**: 利用者は同一ログインセッション内で、連続・同時起動や対応版の別配置・別版・Python/EXE 混在起動をしても、編集画面を1つだけ使用できる。
- [ ] **V110-START-02**: 利用者は正常終了・強制終了・起動途中の異常終了の後に再起動でき、残留ロックで起動不能にならない。
- [ ] **V110-START-03**: 利用者は排他判定や既存画面との連絡に失敗したとき、その失敗を「起動済み」と区別して認識できる。後続起動は追加の編集画面を作らず、有限時間で終了する。

### 既存画面への復帰

- [ ] **V110-FOCUS-01**: 利用者は2回目の起動操作で既存画面へ戻れる。最小化中は復元され、OS が許可すれば前面表示され、拒否時には視覚的な通知で既存画面を見つけられる。
- [ ] **V110-FOCUS-02**: 利用者は2回目の起動後も、未保存の編集、Undo/Redo、OCR の進行、開いているモーダルダイアログの操作を失わず続行できる。

### 設定読込・保存失敗の通知

- [ ] **V110-CFG-01**: 利用者は設定の破損・読取不能などの読込失敗を、画面構築後の通知で認識できる。初回の設定ファイル不存在は警告せず既定値で起動する。
- [ ] **V110-CFG-02**: 利用者は設定保存の失敗と、その変更が次回起動に保存されていないことを通知で認識できる。失敗した保存を成功したと表示しない。
- [ ] **V110-CFG-03**: 利用者の既存設定ファイルは、読込失敗後に既定値を自動保存する処理や、保存途中の失敗によって破壊・無断上書きされない。
- [ ] **V110-CFG-04**: 利用者は同じ設定エラーが繰り返されても、重複通知やダイアログの連打で編集操作を妨げられない。

### サンプル配布・ビルド

- [ ] **V110-DIST-01**: 配布担当者は2種のサンプルプロンプトの正本をビルド出力先の外でソース管理でき、出力先の再作成で正本を失わない。
- [ ] **V110-DIST-02**: 配布担当者は文書化した同じビルド手順を初回・再ビルドで実行し、2サンプルが配布 EXE と同階層に存在して正本と内容一致することを機械確認できる。利用者は配布サンプルを既存の外部プロンプト利用手順で使用できる。
- [ ] **V110-DIST-03**: 利用者が編集した設定・実利用プロンプトは、アプリ起動や再ビルド・配布物の反映によって無断で消去・上書きされない。

### 品質保証・リリース

- [ ] **V110-QA-01**: 保守担当者は起動競合・初期化失敗・設定 I/O 障害・同梱不備を自動テストで再現でき、プロジェクト必須の lint・format・構文確認・全テストを合格させられる。
- [ ] **V110-QA-02**: 検証担当者は Windows 11 の Python 各起動経路と実配布 EXE で、起動・画面復帰・設定通知・同梱の受入結果を確認し、未実施項目を合格と混同せず記録できる。
- [ ] **V110-QA-03**: 利用者はアプリ・README・開発履歴から整合した v1.10.0 の版番号と変更内容、未対応旧版・OS 前面化制約の説明を確認できる。

## Acceptance Criteria and Validation

### 起動・画面復帰

- 起動判定はメイン編集画面を作る前に行い、後続のアプリ本体プロセスは残留しない。最初のプロセスの初期化中に再起動したケースも検証する。
- 同一セッション・別セッション、対応版の別配置/版、`python pagefolio.py`・`python -m pagefolio`・配布 EXE の組合せを対象とする。排他未対応の旧版は保証外であることを明記する。
- 正常終了・強制終了・初期化例外の後に再起動できることと、終了確認をキャンセルした場合には排他が維持されることを確認する。
- 判定/通信 API の失敗を注入する。権限差で既存画面に連絡できない場合も追加画面を許さず、その理由を通知する。具体的な待機上限は Phase 4 の計画で定義する。
- 最小化、他アプリ前面、未保存編集、Undo/Redo 履歴あり、OCR 実行中、モーダル表示中を確認する。OS 前面化拒否は制御した失敗注入と実機の両観点で扱う。

### 設定

- 初回不存在、破損 JSON、読取不能、書込不能、`os.replace` 失敗を区別して検証する。
- 保存失敗の通知は設定を保存する全 UI 経路で確認する。UI 再構築で警告が消失したり、失敗の直後に保存成功を表示したりしない。
- 読込失敗後の自動保存は原本を保護する。明示的な復旧・再保存の操作設計は Phase 5 で決め、無確認で既存原本を置換しない。新しい汎用復旧ツールは要求しない。
- 連続する同一原因の通知は集約する。通知の集約単位・再通知条件は Phase 5 で定義する。
- 既存の API キー非永続化・原子的置換を維持し、通知/ログにも機密値を出さない。新しい設定保存先への移行は要求しない。

### 配布・プロジェクト品質ゲート

- 対象サンプルは `ocr_custom_prompt_sample.md` と `ocr_summary_prompt_sample.md`。実利用ファイル `ocr_custom_prompt.md` / `ocr_summary_prompt.md` と区別する。
- 元ファイルを保全したうえでクリーンビルドと再ビルドを行い、両回で2サンプルの存在と SHA-256 一致を確認する。既存の編集済み設定/プロンプトを置いた条件でも非破壊性を確認する。
- 必須チェック: `ruff check .`、`ruff format .`、`python -c "import ast; ast.parse(open('pagefolio.py', encoding='utf-8').read())"`、単一プロセスの全件 `pytest`。失敗・ERROR・クラッシュなしで完走し、無断のテスト除外をしない。
- フェーズ完了時は `/gsd-validate-phase` を実行し、対応する `NN-VALIDATION.md` を `status: validated` にする（PROJECT.md の DoD に従う）。
- 研究時点の全件テスト成功は既存コードの基準値であり、本要件が実装・検証済みであることを意味しない。GUI・配布 EXE の受入は今後実施する。

## Future Requirements

- **V110-F-01**: 起動時の PDF 引数を既存画面へ転送する（未保存編集・パスワード付き PDF の扱いを別途設計）。
- **V110-F-02**: 最近使ったファイル・閲覧位置を復元する。
- **V110-F-03**: 異常終了後の未保存編集を復旧する。
- **V110-F-04**: 外部プロンプトファイル保存失敗を設定 UI で通知する（`save_prompt_file()` 呼出し側の結果処理）。

## Out of Scope

| 対象 | 理由 |
|------|------|
| 排他機構未対応の旧版 EXE との相互排他 | 旧版が同じ起動判定へ参加しないため、今回の共通機構による保証対象にしない（ユーザー確認済み） |
| PC 全体・複数ログインセッションをまたぐ起動制限 | 同一ログインセッション単位を採用 |
| OS の前面化制約を迂回する強制フォーカス取得 | 通常の前面化試行と視覚通知を採用（ユーザー確認済み） |
| OCR 共通化・既存技術的負債の一括解消 | 採用された4項目以外へ作業を拡大しない |
| 実 API UAT・課金を伴う評価 | 今回の起動・設定・配布改善とは独立。既存の保留記録を維持 |
| 自動更新機構・汎用設定復旧ツール | ファイルの非破壊性は保証するが、新しい更新/復旧製品機能は追加しない |
| `pyproject.toml` 編集 | プロジェクト規約で禁止 |
