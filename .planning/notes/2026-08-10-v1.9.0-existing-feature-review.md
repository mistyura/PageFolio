## 3. 詳細

### V190-REV-01: パスワード保護PDFの暗号化が外れる

`pagefolio/file_ops.py` の `_save_as()` は、認証済みDocumentを `self.doc.save(path)` で保存しており、`fitz.PDF_ENCRYPT_KEEP` を指定していない。

同様に、インクリメンタル保存失敗時の `_overwrite_current_file()` は `self.doc.tobytes(**save_kwargs)` で再生成するため、暗号化維持指定がない。

確認した挙動:

- 入力PDF: `needs_pass == 1`
- 認証後に現行 `_save_as()` と同じ方法で保存
- 保存先PDF: `needs_pass == 0`

さらに、保存後も `pdf_has_password` の状態は更新されないため、実ファイルとUI状態が不整合になる。

推奨対応:

- 通常の保存・名前を付けて保存・上書きフォールバックで暗号化維持方針を統一する。
- 暗号化解除は既存の明示的な「パスワード解除」操作だけに限定する。
- 暗号化PDFのSave Asとインクリメンタル保存失敗フォールバックの回帰テストを追加する。

主な根拠:

- `pagefolio/file_ops.py:626-646`
- `pagefolio/file_ops.py:648-673`
- `pagefolio/file_ops.py:688-708`
- `tests/test_password.py` に通常保存経路の暗号化維持テストがない

### V190-REV-02: OCR OFFをバッチOCRが迂回する

ツールメニューのバッチOCRはOCR設定が `off` でも開くことができ、実行開始時にもOFF判定がない。一方、`build_provider()` は `off` をLM Studioとして扱う。

そのため、通常のOCRボタンは無効でも、バッチOCRからLM Studio接続を開始できる。LM Studio URLにリモート接続先を設定している場合は、意図しない送信にもつながり得る。

推奨対応:

- `off` をプロバイダ生成可能な値として扱わない。
- バッチOCRの起動時と開始時にOFFガードを設ける。
- OCR OFF時にバッチ処理が開始されない回帰テストを追加する。

主な根拠:

- `pagefolio/app.py:314-318`
- `pagefolio/dialogs/batch_ocr.py:627-650`
- `pagefolio/ocr.py:431-441`

### V190-REV-03: 複数ファイル挿入の途中失敗が非トランザクション

`_do_insert()` は各ファイルを現在のDocumentへ順番に直接挿入する。後続ファイルで例外が発生すると、先に挿入したページは残る一方、不完全なUndo状態だけが削除される。

また、`insert_pdf()` で例外が発生した場合、開いた挿入元Documentが `finally` で閉じられない。

推奨対応:

- 一時Documentで全入力を構築し、全件成功後に本体へ反映する。
- または、挿入済みページ数を追跡して例外時に自動ロールバックする。
- 挿入元Documentを必ず `finally` で閉じる。
- 2件目で失敗するテストを追加し、ページ数とUndoスタックが処理前と一致することを確認する。

主な根拠:

- `pagefolio/page_ops.py:756-790`

### V190-REV-04: ページ複製失敗後に不正なUndo履歴が残る

`_duplicate_page()` は実処理より先に `_save_undo("duplicate")` を呼ぶ。複製前に例外が発生しても履歴が残り、その後のUndoは「複製されたはずの次ページ」を削除する。

推奨対応:

- 操作成功後にUndo状態を確定する。
- または例外時に、今回追加したUndo状態だけを確実に破棄する。
- 複製処理を意図的に失敗させ、既存ページとUndoスタックが変化しないテストを追加する。

主な根拠:

- `pagefolio/page_ops.py:177-193`
- `pagefolio/file_ops.py:257-263`
- `pagefolio/file_ops.py:382-390`

### V190-REV-05: キャンセル後も外部プロンプトファイルが変更される

LLM設定画面は外部プロンプトファイルについて「適用時に保存」と表示するが、テンプレートを切り替えた時点で `ocr_custom_prompt.md` と `ocr_summary_prompt.md` を上書きする。キャンセルボタンはダイアログを閉じるだけで、ファイルを元へ戻さない。

外部ファイルは設定値より優先されるため、ユーザーがキャンセルしても次回OCRのプロンプトが変化する。

推奨対応:

- 外部ファイルへの書き込みをApply時へ一本化する。
- ライブ連動を維持する場合は、ダイアログ開始時の内容を保持し、Cancel時に復元する。

主な根拠:

- `pagefolio/dialogs/llm_config/sections.py:1142-1151`
- `pagefolio/dialogs/llm_config/sections.py:1207-1247`
- `pagefolio/dialogs/llm_config/dialog.py:445-469`

### V190-REV-06: テンプレート編集中の切替で入力が消える

外部プロンプトファイルが存在せず、アクティブテンプレートが選択済みの場合、`_has_unsaved_template_changes()` は常にFalseを返す。入力欄を編集して別テンプレートへ切り替えると、確認なしで編集内容が置き換えられる。

未選択状態の自由入力については回帰テストがあるが、選択済みテンプレートを編集したケースは対象外になっている。

推奨対応:

- ファイル連動の有無にかかわらず、入力値と現在のアクティブテンプレート値を比較する。
- 選択済みテンプレート編集後の切替確認テストを追加する。

主な根拠:

- `pagefolio/dialogs/llm_config/sections.py:1158-1185`
- `tests/test_provider_ui.py:2249-2297`

### V190-REV-07: Undo/Redo復元失敗時に履歴を失う

`_undo()` と `_redo()` は対象状態をスタックから先に `pop()` し、例外処理なしで `_restore_state()` を実行する。復元処理が失敗すると、履歴が失われたうえ、Documentが部分的に変更される可能性がある。

推奨対応:

- 復元失敗時に元の状態をスタックへ戻す。
- 部分適用があり得る操作はロールバック可能な単位へ分割する。
- `duplicate`、`merge`、`merge_resize` に対する do→undo→redo→undo の4手往復テストを追加する。

主な根拠:

- `pagefolio/file_ops.py:175-197`
- `.planning/STATE.md` の既存Blockers/Concernsにも水平展開未実施として記録済み

### V190-REV-08: OCRプロバイダ情報が分散している

環境変数は `ocr_providers/registry.py` に集約されているが、実行可能プロバイダ一覧、クラウド判定、表示名、モデル名、APIキーエラー、送信先ホスト、フォールバック候補は複数モジュールに重複している。

ChatGPT追加時に想定される主な変更面:

- `pagefolio/ocr_providers/registry.py`
- `pagefolio/ocr.py` のファクトリとクラウド判定
- `pagefolio/dialogs/llm_config/sections.py` のプロバイダ・フォールバック一覧
- `pagefolio/dialogs/llm_config/dialog.py` の設定収集
- `pagefolio/ocr_dialog.py` の表示名、モデル、送信先、APIキー処理
- `pagefolio/dialogs/batch_ocr.py` のクラウド判定、コスト確認、送信先
- `pagefolio/lang.py` の表示文言

推奨対応:

- ChatGPT追加前にプロバイダメタデータの責務を整理する。
- 少なくともキー、表示名、クラウド種別、環境変数、既定モデル、送信先、フォールバック可否を一元定義する。
- `registry.py` の標準ライブラリのみという独立性制約は維持し、必要に応じて非機密メタデータ用レジストリを別モジュールへ分離する。

## 4. 検査結果

| 検査 | 結果 |
|------|------|
| `ruff check . --no-cache` | 合格 |
| `ruff format --check . --no-cache` | 87ファイルすべて整形済み |
| `pytest -q -p no:cacheprovider` | 1085 passed, 24 errors |
| 暗号化PDFのSave As相当再現 | 保存先がパスワード不要になることを確認 |
| Tkinter単体起動 | `_tkinter.TclError` で失敗 |

24件のテストエラーはアサーション失敗ではなく、Python 3.14.6環境でTkinterが `init.tcl` を使用可能な状態として読み込めないことによるセットアップエラーだった。対象は主にバッチOCR、OCRダイアログ配置、プラグインダイアログ、ショートカットダイアログ、トーストのGUIテスト。

`init.tcl` 自体はPythonインストール先に存在するため、コード不具合と断定せず、Python/Tcl/Tk実行環境の修復後に再実行する。

## 7. v1.9.0計画へ取り込む際の判断基準

- P0/P1はChatGPT追加より前に完了する。
- 失敗時にDocument・Undo履歴・外部ファイルが操作前の状態へ戻ることを受け入れ条件に含める。
- OCR OFFは通常OCR、バッチOCR、プラグイン経路を含む全実行経路で同じ意味にする。
- ChatGPT追加では「設定保存にAPIキーを含めない」「送信先を明示する」「フォールバック時に再確認する」という既存の安全境界を維持する。
- Tkinter環境を修復し、GUIを含む全テストが完走するまでリリースゲート合格とはしない。
