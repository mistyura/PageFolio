# W11 別セッション確認を準備できない場合の判断案

利用者回答: 「使える別ユーザー・別セッションがない」。現行契約ではW11を実施できず、出荷は未承認のまま。以下は案であり、REQUIREMENTS・PLAN・監査コード・台帳の判定は変更していない。

## 案A: 現行の保証範囲を維持する

既存の別Windowsログインセッションを使える検証環境を別途準備し、W11のPython/実EXEの2行を実測する。準備できるまでW11はnot-runで出荷停止。アカウント新設・資格情報取得を今回の自動作業に追加しない。

## 案B: 今回のリリース保証を単一ログインセッションでの利用に限定する

利用者が明示承認した場合に限り、複数Windowsログインセッションを同時使用する環境の動作保証を今回のリリース対象外として再計画する。

- 対象は `W11/other-session@script` と `W11/other-session@production-exe` の2行のみ。原記録はnot-runのまま履歴として残し、passへ変換しない。
- 別セッションでの各1画面・同セッションへの復帰・元状態維持は未確認と配布文書に明記し、将来の受入項目として追跡する。
- 同一セッションの排他/前景/未保存編集/OCR、UAC両方向、DPI、実OS拒否、設定保護、WR-01を含む残り108行は引き続き必須。自動試験、未解決の製品欠陥、Security highを免除しない。
- 承認後は PROJECT.md / REQUIREMENTS.md / 06-CONTEXT.md / 06-05・06-06-PLAN.md / UAT・CARRYOVER・VALIDATION / 監査契約を整合させ、独立計画チェックと必要な回帰検証を行う。現行監査をその場でskipさせない。
- 配布文書がbuild入力となるため、変更後の新世代buildと必要な再検証が発生する。承認だけで出荷可能にはならない。

判断根拠: `06-06-PLAN.md` は「準備不能W11は他の独立項目の記録後にもnot-runを残し本task未完了」「再計画には利用者の明示承認が必要」と定める。現在の「出荷停止状態を解消して」は修正・検証を進める指示として扱い、保証範囲縮小の明示承認とはみなしていない。
