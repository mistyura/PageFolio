<objective>
パスワード保護 PDF の保存経路から「意図しない平文化」を構造的に排除する。PyMuPDF 1.28.0 は `Document.save()` / `Document.tobytes()` を `encryption` 引数なしで呼ぶと暗号化を保持しない（RESEARCH.md で実行時検証済み）。本プランは D-01 / D-02 / D-03 に従い、`_save_as` へ `encryption=fitz.PDF_ENCRYPT_KEEP` を無条件付与し、`_overwrite_current_file` では `setdefault` による安全側既定化を行い、`pdf_has_password` を保存 kwargs から論理導出する単一ヘルパーへ集約する。

Purpose: マイルストーン共通の受け入れ条件「操作が失敗しても・成功しても、ユーザーが明示的に指示していない状態変化を起こさない」の最初の実証。暗号化の黙示的な喪失は、ユーザーのファイルの機密性を直接毀損する high 深刻度の情報漏洩。
Output: `pagefolio/file_ops.py` の保存3経路（+ 縮小保存）の暗号化維持、`derive_pdf_has_password` 純関数、`tests/test_password.py` の実ファイル `needs_pass` 検証回帰テスト群。
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| アプリ内 Document → ファイルシステム | 暗号化された PDF の内容が平文としてディスクへ書き出され得る境界。`Document.save()` / `Document.tobytes()` の `encryption` 引数がこの境界の唯一の制御点 |
| ユーザーの明示操作 → 暗号化状態の変更 | 「🔒 パスワード → 設定 / 解除」だけが暗号化状態を変えてよい。通常の保存操作がこの境界を越えてはならない |
| UI 表示（`pdf_has_password`）→ 実ファイルの暗号化状態 | 表示が実態と乖離すると、ユーザーは保護されていないファイルを保護済みと誤認する |
