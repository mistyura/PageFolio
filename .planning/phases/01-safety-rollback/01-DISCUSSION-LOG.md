## 保存時の暗号化契約

### Q1. パスワード保護PDFを「名前を付けて保存」したときの振る舞い

| Option | Description | Selected |
|--------|-------------|----------|
| 無確認で常に維持 | Save As に PDF_ENCRYPT_KEEP を無条件付与。解除は既存の「🔒パスワード → 解除」だけ。V190-SAFE-02 と正面から一致し実装もテストも最小 | ✓ |
| 維持＋保存後に明示通知 | 常に維持しつつ、保存後のステータスに「暗号化を維持して保存しました」を明記。i18n 文言が 1 件増える | |
| Save As 時に毎回確認 | 維持/解除を選ばせるダイアログ。平文コピー導線は短くなるが「解除は明示操作のみ」契約を弱める | |

**Notes:** 平文コピーが必要なユーザーは既存の「パスワード解除」メニューを使う想定。専用導線は Deferred へ。

### Q2. `_overwrite_current_file(path, **save_kwargs)` で encryption 未指定時の既定値

**Notes:** 「安全側デフォルトを関数の構造に埋め込む」という判断基準が、以降の質問でも一貫して適用された。

### Q3. 保存後の `pdf_has_password` を実ファイルと一致させる方法

## OCR OFF の伝え方

### Q1. OCR が OFF のときのツールメニュー「バッチOCR」の見せ方

| Option | Description | Selected |
|--------|-------------|----------|
| メニューをグレーアウト | 項目自体を disabled にして開けなくする。最も強いガード。理由が伝わりにくく、設定変更時の再評価配線が必要 | ✓ |
| 開こうとしたら説明＋LLM設定へ誘導 | 押せるが「OCR が OFF です。LLM設定を開きますか？」と尋ねる。理由と復帰手段が同時に伝わる | |
| 開けるが実行ボタンを無効化 | ファイル投入までは可能、「開始」だけ無効。要件の「起動できない」とは厳密には一致しない | |

**User's choice:** メニューをグレーアウト
**Notes:** 入口で止める方針を選択。理由の伝達は次の質問で補った。

### Q2. グレーアウトの理由をどう伝えるか

| Option | Description | Selected |
|--------|-------------|----------|
| ラベルに「（OCR OFF）」を併記 | OFF の間だけラベルを「バッチOCR（OCR OFF）」にして disabled 化。設定由来だと一目で分かる。i18n 1 件追加 | ✓ |
| ラベルは変えず disabled のみ | 最小実装。OCR ボタンも同じく無効化されるので文脈で察しうるという判断 | |
| メニュー直下に無効理由行を追加 | 「→ LLM設定でプロバイダを選択してください」という案内項目を OFF 時のみ出す。メニュー構造が動的に変わる | |

**User's choice:** ラベルに「（OCR OFF）」を併記
**Notes:** Tk の disabled メニュー項目はクリックイベントを取れないため、ダイアログ／ツールチップでの説明は選択肢に入れられなかった。

### Q3. `build_provider()` で `off` を生成不可にする際の空文字 `""` の扱い

| Option | Description | Selected |
|--------|-------------|----------|
| off のみ例外、"" は従来通り | off は専用例外を送出。"" (ocr_provider キーがない旧 settings) は LM Studio として後方互換維持 | ✓ |
| off と "" の両方を生成不可に | 意味論は演繹的だが、旧 settings を持つユーザーが突然 OCR を使えなくなるリスク | |
| 例外ではなく None を返す | 呼び出し側で None チェック。チェック忘れが遠い場所の AttributeError として現れる | |

**User's choice:** off のみ例外、"" は従来通り
**Notes:** 既存ユーザーの設定ファイルを壊さないことを優先。

## 失敗時ロールバックの方式と通知

### Q1. 複数ファイル挿入のトランザクション化方式

| Option | Description | Selected |
|--------|-------------|----------|
| 挿入ページ数を追跡して巻き戻し | 従来どおり逐次挿入し、例外時は挿入数を使って delete_page で巻き戻す。追加メモリゼロ | ✓ |
| 一時Documentで全件構築してから反映 | 本体は成功まで一切触らないので最も安全だが、挿入ファイル群を丸ごとメモリに抱える | |
| 両方（件数で切り替え） | 小規模は一時Doc、大規模は追跡巻き戻し。失敗経路が 2 本になりテスト・保守コストが倍増 | |

**User's choice:** 挿入ページ数を追跡して巻き戻し
**Notes:** Core Value（大 PDF 性能）を基準にメモリピークを避ける判断。

### Q2. 巻き戻し自体が失敗した場合（二重失敗）の扱い

| Option | Description | Selected |
|--------|-------------|----------|
| 警告ダイアログ＋Undo履歴は残す | 「自動復元に失敗しました。N ページが挿入されたままです。Ctrl+Z で戻せます」と明示し、実挿入数を反映した Undo state を残す | ✓ |
| 警告のみ、Undo履歴は破棄 | 不正確な Undo で別ページを消す事故は防げるが、ユーザーは手動削除するしかなくなる | |
| 例外をそのまま伝播 | 専用ハンドリングを作らない。万一のとき部分適用が無警告で残り受け入れ条件に反する | |

**User's choice:** 警告ダイアログ＋Undo履歴は残す
**Notes:** マイルストーン共通の受け入れ条件「部分適用を無警告で残さない」に照らした判断。

### Q3. 「Undo 記録の後置」パターンの水平展開範囲

| Option | Description | Selected |
|--------|-------------|----------|
| 要件対象（duplicate/insert）のみ＋棚卸し記録 | 修正は 2 経路だけ。全 op をグレップして「先置きのままの op 一覧」を記録し次マイルストーン候補にする | ✓ |
| 共通ヘルパーを作って全 op へ適用 | 仮登録→commit/rollback のコンテキストマネージャで rotate/crop/delete も一気に載せ換え。構造的には最強だが変更面と回帰リスクが大 | |
| 共通ヘルパーを作るが適用は対象 op のみ | マネージャは新設し配線は 2 経路のみ。次マイルストーンの土台になる | |

**User's choice:** 要件対象（duplicate/insert）のみ＋棚卸し記録
**Notes:** フェーズ境界を守る判断。棚卸し結果は Deferred Ideas 経由で次マイルストーンへ引き継ぐ。

### Q4. Undo/Redo 復元失敗時のユーザーへの伝え方

| Option | Description | Selected |
|--------|-------------|----------|
| エラーダイアログ | messagebox で「Undo に失敗しました。履歴は保持されています」と即時提示しブロック | ✓ |
| 再試行付きトースト | 既存 ToastManager を流用した非モーダル通知。作業は止めないが見落としリスクと「再試行しても同じ失敗」の可能性 | |
| ステータスバーのみ | 既存の undo_empty / undo_done と同じく `_set_status`。実装最小だが重大度に対して控えめすぎる | |

**User's choice:** エラーダイアログ
**Notes:** 復元失敗は稀かつ重大で、見落とされると壊れた前提のまま編集が続くため。

## 設定UIのApply/Cancel契約

### Q1. Apply 押下時に外部プロンプトファイルへ何を書くか

| Option | Description | Selected |
|--------|-------------|----------|
| 入力欄の現在値を書く | 閉じる瞬間に画面で見えていた内容がそのままファイルへ反映される WYSIWYG。テンプレート未選択の自由入力も自然に扱える | ✓ |
| アクティブテンプレートの保存値を書く | v1.8.0 D-07 の不変条件を Apply 時点で維持。未保存の入力はファイルへ行かず「Apply したのに反映されない」と見える | |
| 外部ファイルが存在するときだけ現在値を書く | 従来のファイル連動モード判定を残し書き込みタイミングだけ Apply へ移す。変更面は最小だが仕様の分かれ道は残る | |

**User's choice:** 入力欄の現在値を書く
**Notes:** v1.8.0 D-07 の不変条件は「Apply 時点の入力欄内容」へ置き換わる。

### Q2. Apply 時に外部ファイルがまだ存在しない場合

| Option | Description | Selected |
|--------|-------------|----------|
| 存在するファイルのみ更新 | 既存のオプトイン仕様（ユーザーが自分でファイルを置いたときだけ連動）を維持。作業ディレクトリに md が勝手に増えない | ✓ |
| Apply で常に作成する | 外部ファイルが常に設定の写しになり優先関係の混乱が消えるが、今までファイルを使っていなかったユーザーの振る舞いが黙って変わる | |

**User's choice:** 存在するファイルのみ更新
**Notes:** 外部ファイルは設定値より優先されるため、勝手な生成は挙動変化として大きい。

### Q3. CFG-02 の未保存判定で入力値を何と比較するか

| Option | Description | Selected |
|--------|-------------|----------|
| 常に保存済みテンプレート値と比較 | `prompt_file_exists()` 分岐を削除し、入力欄 vs `get_template()` の 1 経路に統一。要件文と直接一致 | ✓ |
| 保存値比較＋外部ファイル内容も考慮 | ファイルがあればファイル内容を基準にする。外部編集ユーザーには正確だが判定経路が 2 本に戻り同型バグの再発余地が残る | |

**User's choice:** 常に保存済みテンプレート値と比較
**Notes:** アクティブテンプレート未選択時の「自由入力の有無だけ見る」既存ロジックは維持する。

### Q4. Apply 一本化後の注記文言

| Option | Description | Selected |
|--------|-------------|----------|
| 既存文言のまま | 「適用時に保存」という表示はもともと正しく、実装が文言に追いつくだけ。i18n 差分ゼロ | ✓ |
| Cancel の影響を明記 | 「キャンセルすると外部ファイルへの変更も破棄されます」を追記。契約変更が既存ユーザーにも伝わるが文言が長くなる（日英 2 件追加） | |

**User's choice:** 既存文言のまま
