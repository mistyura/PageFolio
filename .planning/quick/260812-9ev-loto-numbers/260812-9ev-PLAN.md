# Quick Plan 260812-9ev — ブランチ運用ルールを loto/numbers に合わせる

## 背景

PageFolio のブランチ運用ルールが姉妹プロジェクト（loto / numbers）と食い違っている。

| 項目 | PageFolio（現状） | loto | numbers |
|------|------------------|------|---------|
| 規約の置き場所 | `docs/DEVELOPMENT.md` + `CONTRIBUTING.md` | `docs/DEVELOPMENT.md` | `docs/DEVELOPMENT.md` |
| ブランチ命名 | `fix/` `feat/` `docs/` `refactor/` + 短い説明 | `feature/v<バージョン>` | doc は `feat/<name>`、実運用は `feature/v<バージョン>` |
| main への直接コミット | 明示なし（実際は直接コミット多数） | 禁止と明記 | 保護ブランチとして明記 |
| コミットメッセージ | 日本語（プレフィクスなしの例） | Conventional Commits 準拠の日本語 | Conventional Commits 準拠の日本語 |
| PR 前ゲート | ローカル ruff + pytest | `make lint` / `make test` + CI green | `make lint` / `make test` + CI green（`test (3.12)` 必須） |

実履歴の確認結果:

- loto: `Merge pull request #36 from mistyura/feature/v0.18.0`, `#35 feature/v0.17.1`, `#34 feature/v0.16.0`
- numbers: `Merge branch 'feature/v0.17.0'`、リモートに `origin/feature/v0.18.0`（doc の `feat/<name>` 表記は旧運用で実態から遅れている）
- PageFolio: `dev/v1.8.0`, `dev/v1.7.x`, `feature/v1.5.0-improvements` と揺れている

→ 2 プロジェクトの現行実態である `feature/v<バージョン>` を PageFolio の正とする。

## 決定事項（前提）

1. **統合ブランチは `main`。`main` へ直接コミットしない**（loto L250 / numbers L182 準拠）
2. **機能ブランチは `feature/v<バージョン>`**（例: `feature/v1.10.0`）。バージョンに紐づかない単発作業のみ `feat/<短い説明>` を許容（numbers L183 の記法を残す）
3. **PR は `main` を対象。タイトル・本文は日本語**
4. **コミットメッセージは Conventional Commits 準拠の日本語** — `type(scope): 日本語の説明`。type は `feat` / `fix` / `docs` / `test` / `refactor` / `chore` / `build`
5. **コミット前ゲートは `ruff check . && ruff format .` と `pytest`** — PageFolio に CI ワークフローは存在しないため、loto/numbers の「CI green を確認」はローカルゲート（CLAUDE.md のリリースゲート）へ読み替える
6. **branch protection は未適用**（numbers の `.github/branch-protection.yaml` 相当は CI 必須チェックが前提のため PageFolio では作成しない）。この差分は doc に明記する
