# Quick Plan 260812-9tv — config.json の `git` セクションと PROJECT.md のブランチ運用節を loto に合わせる

## 背景

前タスク 260812-9ev で `docs/DEVELOPMENT.md` / `CONTRIBUTING.md` のブランチ規約を loto/numbers と統一したが、
**設定（`.planning/config.json`）と GSD エージェント向け規範（`.planning/PROJECT.md`）は未対応**のまま。
実際、260812-9ev 自身が `branching_strategy: "none"` / `quick_branch_template: null` により `main` へ直接コミットされた。

loto は 2026-08-12 の quick `260812-0z0` で同じ是正を実施済み（コミット `d825a22` / `7038e1a` / `d347406`）。本タスクはそれを参考にする。

## 確定事項（ユーザー承認済み）

1. **適用範囲は #1（config の `git` 3 キー）+ #2（PROJECT.md `## ブランチ運用` 節）のみ。** `## Constraints` 節の新設・`## フェーズ完了 DoD` + 機械ゲートテストは今回スコープ外
2. **発効は v1.10.0 以降**と明記する（v1.9.0 は 2026-08-11 出荷済み・次マイルストーン未定のため）。確立日は 2026-08-12
3. `git` セクション以外（`workflow` / `ship` / `model_policy` / `granularity` 等）は**一切変更しない** — PageFolio 固有の設定であり丸コピーは禁止

## 3 プロジェクトの現況（ユーザー指摘により再確認）

初回調査で numbers の `main` を参照し「loto の SUMMARY にある numbers 同値化は事実と異なる」と判断したが、**これは誤り**。
numbers は現在 `feature/v0.18.0` をチェックアウトしており、**同ブランチに `milestone` 戦略と `## ブランチ運用` 節が揃っている**。
numbers 自身のルール（フェーズ作業は `feature/v{version}` 上で行い、`main` へは `/gsd-complete-milestone` 時に一度だけ統合）に従った結果、`main` 側が未反映なだけだった。

| プロジェクト | 参照すべきブランチ | `branching_strategy` | `## ブランチ運用` 節 | 発効 |
|---|---|---|---|---|
| numbers | `feature/v0.18.0`（進行中） | `milestone` | あり（**パターンの原典**） | v0.18.0 開始時・2026-08-12 確立 |
| loto | `main`（v0.18.0 出荷済み・次未定） | `milestone` | あり（numbers を踏襲） | v0.19.0 以降・2026-08-12 確立 |
| **PageFolio** | `main`（v1.9.0 出荷済み・次未定） | **`none`** | **なし** | **本タスクで v1.10.0 以降** |

→ loto と numbers は同一状態。PageFolio のみ未対応であり、**3 者を揃えるのが正しい目標**。
→ 節の本文は原典である **numbers の 5 部構成**を踏襲する（loto も同じ構成）。「loto/numbers と同値」と書いてよい。

- **files**: `.planning/config.json`
- **action**: `branching_strategy` を `"none"` → `"milestone"`、`milestone_branch_template` を `"gsd/{milestone}-{slug}"` → `"feature/{milestone}"`、`quick_branch_template` を `null` → `"quick/{num}-{slug}"` へ変更。`create_tag` / `phase_branch_template` は既に loto と同値のため無変更。**`git` 以外のキーは 1 つも触らない**
